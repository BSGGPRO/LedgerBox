# 金钱小模型（0.2.1）

## 1. 先说实话

LedgerBox 现在塞进去的不是 0.5B/1B 大语言模型，而是一个 **5,643 参数的本地分类器**：

```text
11 个语义类别 × 512 个字符 n-gram 哈希桶 + 11 个 bias
= 5,643 个参数
```

它做的是：

- 判断一句话更像餐饮、交通、购物、住房、娱乐、医疗、工资、理财、转账、退款还是其他。
- 在解析器没有明确分类时，给分类建议排序。
- 在 AI 卡片显示“金钱小模型 · 餐饮 84%”。

它不做的是：

- 不生成文本。
- 不生成金额。
- 不覆盖 `QuickEntryParser` 已经明确解析出的分类/账户/金额。
- 不联网、不调用云端 API。
- 不是财务建议。

## 2. 结构

| 项目 | 值 |
|---|---|
| 模型 | 多项逻辑回归（multinomial logistic regression） |
| 特征 | 单字 + 双字 n-gram，FNV-1a 哈希到 512 桶 |
| 类别 | 11 |
| 参数量 | 5,643 |
| 权重 | Int16 量化，base64 内嵌 |
| 推理 | 纯 Swift，无 Core ML、无第三方库 |
| 训练脚本 | `Tools/train_money_brain.py` |
| 权重文件 | `LedgerBox/Features/QuickEntry/MoneyBrainWeights.swift` |

推理流程：

```text
文本 -> 去数字/标点/空白 -> 单字 + 双字 n-gram
     -> FNV-1a 哈希到 512 桶
     -> 11 类线性打分 -> softmax
     -> 置信度 >= 0.42 才显示
```

## 3. 训练数据的边界

`Tools/train_money_brain.py` 使用**合成中文短语**，按类别模板生成，并随机加账户、金额、前后缀。

因此：

- 合成验证集准确率没有现实意义，不能写进宣传。
- 真实银行短信、外卖备注、方言、错别字、英文商户名都可能误判。
- 它只做提示，最终仍要用户确认。
- 若要提高真实准确率，需要脱敏真实语料 + 人工标注 + 重新训练；不能拿用户账本偷偷训练。

## 4. 真正的“小 B 数”模型选项

如果目标是生成式模型，而不是分类器，下面是可选路线。**当前 IPA 没有包含它们**，因为体积、转换工具和运行时都需要单独处理。

| 模型 | 参数 | 许可（以模型卡为准） | 中文 | iOS 现实问题 |
|---|---:|---|---|---|
| Qwen2.5-0.5B-Instruct | 约 0.5B | Apache-2.0 | 较好 | 4-bit 约 300–400MB；需要 Core ML / MLX 转换与 Swift 推理层 |
| SmolLM2-360M-Instruct | 约 0.36B | Apache-2.0 | 较弱 | 体积小，但中文财务语句不是强项 |
| Gemma 2 2B / Gemma 3 270M | 2B / 0.27B | Gemma Terms | 视版本 | 许可不是 MIT；需要遵守 Gemma 使用条款 |
| Phi-3-mini-4k-instruct | 3.8B | MIT | 一般 | 对手机太重，IPA 会到 GB 级 |
| TinyLlama-1.1B-Chat | 1.1B | Apache-2.0 | 较弱 | 英文为主，中文记账不稳定 |
| FinBERT（110M） | 0.11B | Apache-2.0（以模型卡为准） | 英文金融 | 编码器分类模型，不是聊天/生成模型 |

### 推荐顺序

1. **现在这个 5,643 参数分类器**：立即能跑、无权限、无网络、IPA 只增加十几 KB。
2. **Qwen2.5-0.5B-Instruct 4-bit**：如果确实要“能对话的金钱助手”，这是体积/中文能力比较平衡的路线；但需要 Mac 上转换、单独的模型下载/缓存、几百 MB 空间，以及生成式输出的安全边界。
3. **不要**把 2B/3.8B 直接塞进 IPA：下载、首启、内存、审核和自签都会变复杂。

## 5. 如果以后要接 0.5B

建议做成**可选下载**，不要打进主 IPA：

```text
App 内置规则/分类器
  -> 设置里“下载金钱助手模型”
  -> 下载到 Application Support
  -> Core ML / MLX 本地推理
  -> 只生成“建议”，不直接写账
```

必须遵守：

- 模型许可与 NOTICE。
- 不把账本原文发到网络。
- 生成结果必须经过 `QuickEntryParser` 和用户确认。
- 不能把模型输出直接当金额/分类写库。
- 要有“模型不可用/下载失败”的降级路径。

## 6. 重新训练

```bash
python Tools/train_money_brain.py
```

脚本会覆盖：

```text
LedgerBox/Features/QuickEntry/MoneyBrainWeights.swift
```

然后重新 archive。注意：脚本里的模板和随机种子只用于演示，不是生产语料。
