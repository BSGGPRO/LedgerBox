# LedgerBox 财务规则与边界

本文是 LedgerBox 的财务规则说明书。它描述**产品约定**、**当前源码实现**和**已知缺口**。源码已由 GitHub Actions archive，33 个规则/解析/模型单元测试已在 iOS 模拟器通过；但完整业务流程仍需要真机或人工逐页验收。

---

## 1. 基本原则

1. 只做本地记账，不做网络同步。
2. 金额只使用 `Decimal`；Core Data 使用 `Decimal` 属性，Swift 通过 `NSDecimalNumber` 桥接。
3. `Double` 只允许出现在 UI 比例、进度条、图表和天数取整边界。
4. 金额统一保留两位小数，写入前 `Decimal.rounded(scale: 2)`。
5. 记账日期允许手动选择，但不能晚于当前时间。
6. 使用设备本地时区与操作时间。
7. v1 只按 CNY 展示；`currencyCode` 字段默认 `CNY`，不做汇率换算。

## 2. 16 条边界

| # | 边界约定 | 当前实现 |
|---|---|---|
| 1 | 删除交易必须先回滚账户余额，再删除记录；预算和统计随之重算。 | `LedgerService.delete` 已实现反向余额影响，再 `context.delete` + `save`。 |
| 2 | 转账只生成一条 Transfer 记录，不计入收入/支出；删除时同时回滚转出与转入。 | 已实现；`FinanceEngine.summary` 与 `spending` 都跳过 Transfer。 |
| 3 | v1 使用 CNY；金额字段使用 Decimal；`currencyCode` 默认 CNY。 | 已实现；未做多币种换算。 |
| 4 | 周期记账不做后台定时任务；需要时手动“补记本期”，且可反悔。 | **规则已定，UI 未接入**。当前没有周期记账页面。 |
| 5 | 预算周期：自然月 / ISO 周一到周日；跨月周归开始月份。 | `FinanceEngine.interval(for:.weekly)` 使用 ISO 周；跨月周的“归属月份”没有单独持久化字段，月度报表仍按交易日期汇总。 |
| 6 | 删除分类时保留历史交易；分类软删除；统计归入“其他”。 | `Category.isSoftDeleted` 已存在；统计页对软删除分类显示“其他”。**分类删除 UI 尚未接入**。 |
| 7 | 预算只约束支出，不约束收入、转账。 | 已实现；`FinanceEngine.spending` 只统计 Expense / Refund。 |
| 8 | 退款冲减对应分类支出；金额不能为负。 | 已实现；`summary` 中 `expense -= refund`，`spending` 同样冲减。 |
| 9 | 使用本地时区/操作时间；允许手动日期，但不能晚于当前时间。 | `LedgerService` 校验 `date <= Date()`；区间使用 `Calendar.current`。 |
| 10 | 目标达成后显示“已达成”，停止倒计时与自动分配；超额进入可用余额。 | 目标状态与倒计时已实现；**没有自动分配资金**。买车目标通过专户余额同步。 |
| 11 | 只做 CSV 导出，不保存任何凭据。 | 已实现；`fileExporter` 导出本地 CSV，无网络。 |
| 12 | 至少支持浅色/深色；颜色、圆角、字体集中在 Theme。 | 已实现；`Theme` + `ThemeManager` + `ThemeAccent`。 |
| 13 | 每个主页面有空状态。 | 首页、流水、统计、预算、目标、买车页均有空状态；设置页始终有内容。 |
| 14 | 模板切换只影响未来规则，切换前确认。 | 已实现确认弹窗；模板会更新当前分类/预算/目标规则，但**不删除历史交易、不重置已存金额**。严格“只影响未来”仍需产品确认。 |
| 15 | 买车优先级：修机 4,400 → 买车 25,000 → 溢出下一目标。 | `BuyCarTemplateRules.allocateSurplus` 与买车页已实现。 |
| 16 | 副业收入至少 70% 进当前目标，最多 30% 进备用金；默认 0.7，手动不能低于 0.7，只影响未来收入。 | `splitSideHustle` 已实现；买车页滑块 0.70–1.00。 |

## 3. 交易类型与余额影响

| 类型 | 转出账户 | 转入账户 | 收入/支出统计 |
|---|---|---|---|
| Income 收入 | `+amount` | — | 计入收入 |
| Expense 支出 | `-amount` | — | 计入支出 |
| Refund 退款 | `+amount` | — | 冲减支出 |
| Transfer 转账 | `-amount` | `+amount` | 不计入收入/支出 |

### 新增校验

`LedgerService` 在写入前检查：

- 金额 `> 0`，并用 `roundedToCents()` 保留两位小数；不要调用默认取整的 `Decimal.rounded()`。
- 日期不晚于 `Date()`。
- 账户属于当前 `NSManagedObjectContext`。
- 分类属于当前上下文。
- 转账必须有不同 ID 的转入账户。
- 批量写入时，所有草稿先全部校验，再创建。

### 删除回滚

删除时按原类型反向调整：

- Income / Refund：账户 `-amount`
- Expense：账户 `+amount`
- Transfer：转出账户 `+amount`，转入账户 `-amount`

然后删除交易并保存。保存失败 `rollback()`。

## 4. 汇总公式

### 4.1 区间汇总

```text
income  = Σ Income.amount
expense = Σ Expense.amount - Σ Refund.amount
net     = income - expense
```

Transfer 跳过。

### 4.2 分类支出

```text
spending(category) = Σ Expense.amount - Σ Refund.amount
```

`categoryID == nil` 时统计全部支出。

### 4.3 预算进度

```text
safeLimit = max(limit, 0)
remaining = safeLimit - spent
ratio     = clamp(spent / safeLimit, 0, 1)   // 仅 UI 使用 Double
over      = spent > safeLimit
```

- 总预算 `categoryID = nil`。
- 分类预算按 `categoryId`。
- 只统计启用的预算。
- 月预算使用自然月；周预算使用 ISO 周一到周日。

### 4.4 目标倒计时

```text
remaining = max(target - current, 0)
窗口      = 最近 30 个自然日
有效天数  = 窗口内有非转账交易的去重自然日数
日均结余  = 窗口内净结余 / 有效天数
```

- `remaining == 0`：已达成。
- 有效天数 `< 7`：累积中，不估算。
- 日均结余 `<= 0`：无法估算。
- 否则：`ceil(remaining / 日均结余)`，最小 1 天。

### 4.5 统计序列

- `monthStarts(endingAt:count:)`：以当前月为终点，向前取 N 个月起点。
- `monthlySeries`：每月一个 `LedgerSummary`。
- `dailyCumulativeNet`：从月初到月末逐日累加净额。
- 图表层才把 Decimal 转 Double。

## 5. 模板系统

### 5.1 模板协议

`TemplateRuleProviding` 只提供：

- `kind`
- `title` / `subtitle` / `accentHex`
- `TemplatePlan`

`TemplatePlan` 包含：

- 分类种子
- 预算种子
- 目标种子
- 专户种子
- 提示文案

通用 `FinanceEngine` 不包含任何模板分支。

### 5.2 三套模板

| 模板 | 预算 | 目标 | 专户 |
|---|---|---|---|
| 日常记账 | 总预算 2,000；餐饮 800；交通 300 | 应急金 3,000 | 无 |
| 学生预算 | 总预算 1,500；餐饮 700；学习 200；交通 150 | 旅行基金 2,000 | 无 |
| 买车攒钱 | 总预算 2,500；餐饮 800；交通 300；奶茶 150 | 修机 4,400；买车 25,000；备用金 5,000 | 修机专户、买车专户、备用金 |

### 5.3 模板 upsert 策略

- 分类按 `kind + name` 匹配；软删除分类会恢复。
- 预算按总预算或分类 ID 匹配；重复应用会更新上限/周期/启用状态。
- 目标按 `templateTag` 匹配；保留已有 `currentAmount`。
- 专户按名称匹配；保留已有余额。
- 旧模板 `active = false`，新模板 `active = true`。
- `AppSettings.activeTemplateId` 更新。
- 保存失败回滚。

### 5.4 模板不做什么

- 不删除历史交易。
- 不重置账户余额。
- 不重置目标已存金额。
- 不自动把旧模板的目标/专户迁移到新模板。
- 不清理旧模板遗留的分类、预算、目标或专户。

## 6. 买车场景规则

### 6.1 目标与专户

| 目标 | 金额 | 专户 |
|---|---:|---|
| 修机专户 | 4,400 | 修机专户（`AccountType.goal`） |
| 买车专户 | 25,000 | 买车专户（`AccountType.goal`） |
| 备用金 | 5,000 | 备用金（`AccountType.reserve`） |

优先级：

```text
1. 修机 4,400
2. 买车 25,000
3. 溢出 → 备用金
```

### 6.2 副业收入 70/30

```text
split.goal    = round(amount * ratio)
split.reserve = amount - split.goal
ratio         = clamp(requestedRatio, 0.70, 1.00)
```

- 默认 `0.70`。
- 手动不能低于 0.70。
- 只影响未来收入，不回溯。
- 70% 部分按优先级分配：
  - 先补修机；
  - 再补买车；
  - 溢出进备用金。
- 30% 部分直接进备用金。
- 三条记录通过 `LedgerService.recordBatch` 一次保存。

> 当前实现把副业收入直接作为 Income 进入目标/备用金账户，不先经过现金账户再转账。这样可以避免现金结余重复计算。

### 6.3 打卡与固定收入

| 操作 | 金额 | 频率 | 标签 |
|---|---:|---|---|
| 打卡上班 | 100 | 每天一次 | `car.workshift.yyyy-MM-dd` |
| 固定工资 | 500 | 每月一次 | `car.salary.yyyy-MM` |
| 年度补贴 | 3,000 / 3,500 / 4,500 | 每年每档一次 | `car.subsidy.yyyy.amount` |

这些收入进入现金账户，分类优先使用“工资”。

### 6.4 本月结余结转

```text
现金本月净结余 = 现金账户本月收入 - 现金账户本月支出 + 退款
可结转金额     = min(max(现金本月净结余, 0), max(现金账户余额, 0))
```

- 不含转账。
- 不含直接进入目标/备用金账户的副业收入。
- 按修机 → 买车 → 备用金顺序转账。
- 同一月份只允许一次，标签 `car.surplus.yyyy-MM`。
- 结转后再新增收入，不能再次结转；这是防重复设计。

### 6.5 奶茶预算

- 月度上限 150 元。
- 周上限 2 杯（ISO 周一到周日）。
- 记录一杯时默认 15 元，可改。
- 超过月上限或周杯数达到 2 杯时显示警告。
- 奶茶支出从现金账户扣除，分类“奶茶”。

### 6.6 储蓄纪律

- 目标专户支出或转出时，Add Transaction 页面显示警告。
- 买车页统计本月目标专户支出/转出笔数。
- 备用金支出不触发目标专户警告。
- 当前是警告，不是硬阻止。

### 6.7 目标与专户同步

买车页以专户余额为准：

- 进入页面时 `syncCarGoals()` 把 `SavingsGoal.currentAmount` 同步为专户余额。
- 副业分账、结余结转后再次同步。
- 目标状态按 `current >= target` 设为 achieved，否则 active。
- 冻结目标跳过同步。
- 没有 `SavingsGoal.accountId` 外键；通过 `templateTag` 和专户名称匹配。

---

## 7. 退款与负数

- 退款金额必须为正；不允许录入负数金额。
- 退款不增加收入，而是冲减支出。
- 分类占比中，退款可能让某个分类的净支出变为 0 或负数；统计只展示净额 `> 0` 的分类。
- 如果某月退款大于支出，`LedgerSummary.expense` 可能为负，`net` 会相应增加。这是“冲减”语义，不是错误。

---

## 8. 周预算与跨月

- 周区间使用 ISO 8601：周一到周日。
- 周预算的进度按当前 ISO 周计算。
- 跨月周不会被拆成两段。
- 产品边界说“跨月周归开始月份”；当前源码没有单独的“周归属月份”字段，月度柱状图仍按交易日期归月。若要做严格的“周归开始月”报表，需要新增周维度聚合。

---

## 9. 目标倒计时与达成

- 目标当前金额只用于目标进度与倒计时。
- 目标达成后：
  - `FinanceEngine.savingsCountdown` 返回 `.achieved`；
  - `GoalsView` 显示“已达成”；
  - 不再显示预计天数。
- 没有自动从账户划转资金到目标。
- 买车页的目标金额会与专户余额同步；其他目标仍可手动编辑当前金额。

---

## 10. 数据与删除

- 交易删除是不可撤销操作；UI 有确认。
- 删除交易会回滚余额，预算/统计通过 `@FetchRequest` 重新计算。
- 删除分类的产品规则是软删除；当前没有分类删除 UI。
- 统计页对软删除分类归入“其他”。
- 删除预算不会影响历史交易。
- 删除目标不会影响账户余额。

## 11. 已知实现缺口

1. 周期记账 UI 未接入。
2. 分类管理/软删除 UI 未接入。
3. 账户管理 UI 未接入。
4. `SavingsGoal` 与 `Account` 没有外键关系。
5. 目标达成后的“超额进入可用余额”没有自动划转。
6. 模板切换会更新当前预算/目标规则，严格“只影响未来”需要产品确认。
7. 周预算跨月归属没有独立持久化。
8. 无多币种换算。
9. 33 个 XCTest 已通过；但 UI 流程、真机安装与真实账本仍未验证。

## 12. 手工验收样例

在 Mac 上运行时，可用下面样例检查核心规则：

### 12.1 收入/支出

1. 记录收入 500 → 现金账户 +500，首页本月收入 500。
2. 记录支出 32.50 → 现金账户 -32.50，本月支出 32.50。
3. 记录退款 10（同一分类）→ 现金账户 +10，分类净支出减少 10。

### 12.2 转账

1. 现金 → 储蓄转账 100。
2. 现金 -100，储蓄 +100。
3. 首页收入/支出不变。
4. 删除该转账 → 两边余额回滚。

### 12.3 预算

1. 总预算 2,000，支出 500 → 进度 25%。
2. 支出 2,100 → 超预算，剩余为负。
3. 退款 100 → 支出变为 2,000，刚好不超。

### 12.4 买车

1. 应用买车模板 → 生成 3 个专户、3 个目标、奶茶预算。
2. 副业 1,000，比例 70% → 修机 +700，备用金 +300。
3. 修机已 4,000 时再来 1,000 → 修机 +400，买车 +300，备用金 +300（示例：70% 目标部分 700，先补修机 400，剩余 300 进买车；30% 备用金 300）。
4. 现金本月净结余 500 → 修机先补，剩余进买车/备用金。
5. 奶茶 160 → 月上限警告。
6. 本周第 2 杯 → 周上限警告。
